## 이미 가진 맥미니로 개인 서비스를 운영해보기

열심히 Codex 를 사용하다보니, 의도치 않은 서비스 구현물이 생성되곤 했었다.

AI 는 참 좋은것이, 내가 평소에 가지고 있었던 아이디어를 빠른 시간안에 눈으로 확인하고 직접 사용해볼 수 있도록 빠르게 구현을 해준다.
그래서 생성된 서비스들은 실제로 나한테 의미가 있는 서비스들이 많이 있었다.

물론 완성도에 있어서는 처음부터 각잡고 설계를 하고, 시간을 들여서 분석하고 생성하는것과는 차이가 있지만, 뭐 여러 사람이 사용할 것도 아니고,
나 자신에게 필요한 서비스니깐 눈감아 줄 만 했다. 여기에 더해 디자인도 이제 디자인 시안을 제대로 첨부하면 큰 하자없이 화면 자체는 구현을 해주니 요새는 참 편해졌다고 생각이 든다.
(동시에 프론트엔드 개발을 어떻게 더 심화해 나가야 할지 고민이 늘어나는 현실..)

그런데 늘어나는 서비스를 그냥 토이 프로젝트로 두기에는 아까워서, 실제 서버에 배포하고 활용하려고 하는데 이 때부터는 현실적인 고민에 들어간다.
모든게 꽁짜는 아니니깐, 결국 배포를 진행하게 되면 그것은 비용으로 이어지게 되고, 구현된 서비스들이 많을 수록 비용은 늘어나게 될 것이다.
하나의 서비스를 제대로 정해서 해당 서비스만 제대로 배포한다고 해도 역시나 비용이고, 애초에 그런 서비스는 나 혼자 사용한다기 보단, 여러 사용자를 고려해야하기에
그에 대한 비용도 어느정도 예산에 포함시키기에 계획안에 존재한다 할 수 있겠다.

그렇지만 거의 혼자 유용하게 사용할 만한 서비스 마다 클라우드에 배포를 하는것은 비용적 부담을 느끼게 되었다. 서비스의 규모가 크지않으면 뭐 AWS lightsail 처럼 무료로 사용할 수 있겟지만,
AI 를 활용하는 서비스라면 어느정도 인스턴스의 성능을 고려하지 않을 순 없었다.
특히나 AI 를 on demand 로 활용할 경우 비용은 더욱 증가할 텐데, 비용이 이중으로 나가는것이 부담이 되었다.

그러다 보니, 간단한 서비스정도는 집에 있는 맥미니로 운영이 가능하지 않을까 생각이 들어서, 한번 codex 와 함께 진행해봤다.

## 추가 고정비를 줄이기 위해 선택한 구조와, 직접 운영하며 마주한 문제들

현재 우리집의 맥미니의 성능은 M4·16GB 256GB 디스크 용량을 가진 가장 보급이자 기본형 모델이었다.
그나마 다행인 점은 용량의 부족으로 이미 외장 SSD 2TB 를 연결해놓고 있었고, 썬더볼츠를 통해 입출력 시간을 최소화 시켰었다.
현재 가용할 수 있는 용량은 1.8TB 정도여서 용량 자체는 당장은 문제가 없겠다 판단이 들었다.

램 용량이나, 내장 디스크는 조금 불안하지만, 작은 서비스 한두개 정도는 큰 무리없이 실행할 수 있겠다 싶었고, 일단 별도의 임대료가 없다는 점에서
마음의 짐 하나를 내려놓는 느낌이었다. 이 외 조금 고민했던 부분은

- 전기료 소비량 : 애초에 ssh 원격 접속을 노트북으로 진행하고 있었기에 현재 맥미니는 항상 실행되고 있기에 차이는 없다 판단
- 데이터베이스/스토리지 : 외장 SSD 를 활용하면 적합하겠다 판단
- 백업 진행 : 외장 용량이라면 백업까지 충분히 다룰 수 있겠지만, 사실 백업의 안전성을 위해서라면 같은 디스크에 백업을 진행하는것은 적합하지 않다고 판단

이 외 내가 모르는 분야도 많이 있곘지만, 우선은 일단 서비스를 한번 구동해보는 방향으로 진행하였다.

### 아키텍쳐 설계

외부(브라우저)와 맥미니(서버)의 연결을 아무런 기존 인프라 서비스의 도움 없이 진행하는것은 무모하다고 판단하였다.
즉, 외부와 내부 사이의 연결 통로를 대신 구축해줄 서비스가 필요했다.

어느 서비스가 적합할 지 고민을 하면서 선택한 것은 Cloudflare 였다.
